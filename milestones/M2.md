## Scope decision (this milestone)

The design doc's M2 lists a full editor (project, profile, canon, faction, quest,
scene). Building all of it at once is the classic M2-overreach trap — patterns
get established late and rework is likely. **This milestone delivers the thinnest
vertical slice that proves the architecture end-to-end**, then subsequent
commits extend it.

Decisions (approved by owner 2026-08-05):
- **Scope:** read-only project browser + full character-profile editor + live
  validation + explicit Save. Other editor types (canon/faction/state/quest/
  scene) land in follow-up commits reusing the established patterns.
- **UI stack:** React + Vite + plain CSS. A Node service exposes `@df/storage`
  over a tiny local HTTP API (matches REPO_LAYOUT §2 + Q-D2 Node+Vite).
- **Save model:** explicit Save button → `writeProject`. Edits live in memory
  until then; no autosave thrash (NON_GOALS §3.1 — Git is history).

## What "done" looks like for this slice

A user can:
1. Open the Quarry Seals sample project from disk.
2. Browse every artifact by type (read-only tree).
3. Open any character, edit its full profile (identity, core, opinions,
   knowledge, voice, pressure), with **schema errors surfaced inline** as they
   type, and **integrity issues** flagged.
4. Press **Save** to persist the whole project atomically; reload and see the
   edits survived.

That proves: `storage → HTTP → React → schema validation → storage` works, the
validation-feedback loop is real, and the editor patterns for every other
artifact type are established.
